# Автосборка APK и автообновление ZI Office

## Как это работает

1. Этот репозиторий приватный (в нём лежит ключ подписи), поэтому приложению
   нужен доступ к релизам — он даётся одним из двух способов
   (см. «Одноразовая настройка»):
   - **токен на телефоне** — приложение читает релизы приватного репозитория
     `zigorminsk-debug/ZI-Office` под своим токеном;
   - **публичный репозиторий** `zigorminsk-debug/ZI-Office-Release` — туда
     публикует APK workflow, и он доступен любому устройству без настройки.
2. Какой канал используется, приложение понимает само: есть токен — берёт
   релизы приватного репозитория, нет — смотрит публичный репозиторий обновлений.
3. Любой коммит в `main` или в ветку `arena/*` → workflow «Сборка APK»
   (`.github/workflows/build.yml`): собирает release-APK, прогоняет тесты и
   выкладывает APK **артефактом** — скачать можно со страницы запуска
   (Actions → запуск → Artifacts).
4. Тег вида `v2.24` → workflow «Релиз APK» (`.github/workflows/release.yml`):
   собирает APK версии 2.24 и публикует GitHub Release с файлом
   `ZIOffice-2.24.apk` в публичном репозитории обновлений.
5. Приложение само следит за обновлениями (класс `UpdateManager` +
   `UpdateJobService`):
   - раз в 6 часов, **даже когда приложение закрыто**, оно спрашивает у GitHub
     последний релиз (`.../releases/latest`) и сравнивает версию со своей;
   - если версия новее — **скачивает APK автоматически** (прогресс виден в
     шторке уведомлений);
   - когда загрузка закончилась, показывает уведомление
     «Обновление ZI Office X готово» — нажатие открывает системный установщик;
   - если приложение открыто в этот момент, оно сразу предлагает «Установить»;
   - после перезагрузки телефона слежение продолжается (задание переживает
     перезагрузку), обновление не скачивается повторно — готовый файл
     используется.

   Полностью без подтверждения Android ставить APK не разрешает: обычным
   приложениям оставлено одно системное окно «Установить / Отмена». Всё
   остальное — проверка, загрузка, уведомление — происходит автоматически.

6. Отключить/включить автообновление можно на экране «О программе»
   (переключатель «Обновляться автоматически»). Там же кнопки
   «Установить обновление X» (если файл уже скачан) и
   «Разрешить установку обновлений» (одноразовое системное разрешение).

Номер сборки (`versionCode`) считается из `versionName` автоматически:
`2.24 → 20400`, `2.24.1 → 20401`. Поэтому обновление всегда «новее»
установленной версии, и Android его принимает.

Проверить обновление можно вручную: в главном окне меню «⋮» →
**Проверить обновления** (или долгое нажатие на заголовок → та же кнопка).
Приложение скажет словами, что происходит: «Установлена последняя версия»,
«Автообновление не настроено», «Токен доступа не подошёл или истёк»,
«Не удалось проверить. Проверьте интернет». Когда настройки нет, вместо
тупика появляется кнопка **«Настроить обновления»**.

## Одноразовая настройка (1 минута)

Релизы лежат в закрытом репозитории `zigorminsk-debug/ZI-Office`, поэтому
приложению нужен доступ. Есть два способа — достаточно **одного**.

### Способ 1 (быстрый): токен в приложении

Ничего в GitHub настраивать больше не нужно, публичный репозиторий не нужен.

1. В приложении: **«О программе» → «Настроить обновления»** (или кнопка
   «Настроить», которая появляется, когда обновления недоступны).
2. Нажмите **«1. Создать токен на GitHub»** — откроется страница токена.
3. На странице: Repository access → **Only select repositories** →
   `ZI-Office`; Permissions → Repository permissions → **Contents →
   Read-only**. Затем «Generate token» и скопируйте токен.
4. Вернитесь в приложение, вставьте токен в поле и нажмите
   **«2. Сохранить и проверить обновления»**.

Токен хранится только на телефоне, даёт право только читать релизы и никуда
не отправляется. Проверить, что всё работает: на том же экране нажмите
«Проверить обновления сейчас» — если есть новая версия, приложение сразу
предложит её скачать и установить.

Токен истёк (например, был выпущен на 90 дней) — приложение напишет
«Токен доступа не подошёл или истёк»: выпустите новый и вставьте так же.

### Способ 2: публичный репозиторий для APK

Тогда токен нужен только сборочному workflow, а телефоны обновляются без
настройки — удобно, если приложением пользуются с нескольких устройств.

**Шаг 1.** Создать публичный репозиторий (имя и тип уже подставлены):

**https://github.com/new?name=ZI-Office-Release&visibility=public**

«Create repository» — больше в нём ничего настраивать не нужно.

Хотите другое имя — задайте переменную репозитория `RELEASE_REPO`
(Settings → Secrets and variables → Actions → Variables → New repository
variable) или переопределите её при сборке: `-PreleaseRepo=владелец/имя`.

**Шаг 2.** Токен и секрет:

1. **https://github.com/settings/personal-access-tokens/new**
2. Repository access → **Only select repositories** → `ZI-Office-Release`
3. Permissions → **Contents: Read and write**
4. «Generate token» → скопируйте токен
5. **https://github.com/zigorminsk-debug/ZI-Office/settings/secrets/actions/new**
6. Name: `RELEASE_TOKEN`, Secret: вставьте токен → «Add secret»

> Токен нужен только workflow: он хранится в секрете GitHub и в код не
> попадает. Код ZI-Office и ключ подписи остаются в приватном репозитории.

Пока ничего из этого не сделано, «Релиз APK» всё равно работает: собирает APK,
выкладывает его артефактом и создаёт релиз в приватном репозитории, а в
описании запуска печатает памятку. Автообновление на телефонах при этом
сообщит «Автообновление не настроено» и предложит кнопку «Настроить».

## Что приложение попросит на телефоне (один раз)

| Запрос | Зачем | Если отказать |
|---|---|---|
| «Разрешить уведомления» | сообщить, что обновление скачалось | обновление всё равно скачается, но узнать о нём можно только открыв приложение |
| «Разрешить установку из этого источника» | запустить установщик скачанного APK | приложение откроет нужный экран настроек само, когда вы нажмёте «Установить» |

Ничего вручную скачивать и искать в «Загрузках» не нужно.

## Как выпустить новую версию

**Способ 1 — через сайт (проще):**

1. Actions → «Релиз APK» → **Run workflow** → в поле версии, например, `2.25` → Run
2. Через 2–3 минуты релиз опубликован, приложения предлагают обновление

Версия 2.24 уже выпущена (в приватном репозитории), поэтому первый релиз после
настройки берите `2.25` — тогда обновление увидят телефоны с 2.23 и 2.24.

**Способ 2 — тегом:**

```bash
git tag v2.24
git push origin v2.24
```

В обоих случаях номер версии в APK берётся из тега/поля ввода — файлы править
не нужно. Следующий релиз должен быть **больше** предыдущего (2.25, 2.26 …),
иначе приложение не предложит обновление тем, у кого уже стоит 2.24.

## Как проверить, что автообновление работает

1. Установите свежий APK (например, `ZIOffice-2.27.apk`) — это единственная
   установка «руками», дальше всё автоматически.
2. Выпустите версию выше установленной: Actions → «Релиз APK» →
   Run workflow → `2.28`.
3. Откройте приложение → «О программе» → «Проверить обновления»: версия
   скачается сама и появится кнопка «Установить обновление 2.28» (или
   уведомление, если приложение закрыто).
4. Нажмите «Установить» и подтвердите одно системное окно — версия обновится,
   данные и настройки сохранятся.

Слежение в фоне запускается не сразу: Android даёт первое выполнение
периодического задания в течение нескольких часов после включения телефона.
Кнопка «Проверить обновления» работает мгновенно.

## Если автообновление не работает — что проверить

Откройте в приложении меню «⋮» → «Проверить обновления» и смотрите текст:

| Что показывает приложение | Что это значит |
|---|---|
| «Автообновление не настроено» | не выполнен ни один способ настройки — нажмите кнопку «Настроить обновления» |
| «Токен доступа не подошёл или истёк» | выпустите новый токен (Contents: Read-only для ZI-Office) и вставьте его на экране «Настройка обновлений» |
| «Нет доступа к релизам zigorminsk-debug/ZI-Office» | токену не разрешён этот репозиторий — проверьте, что он выпущен именно для `ZI-Office` |
| «Установлена последняя версия 2.23» | релиз новее вашей версии не опубликован |
| «Не удалось проверить. Проверьте интернет» | нет сети / блокировка api.github.com |
| Диалог «Доступна версия 2.28» | всё работает — версия скачается сама |
| «Версия 2.28 скачана и ждёт установки» | файл готов, нажмите «Установить обновление 2.28» |
| Уведомление не приходит | отключены уведомления приложения: Настройки Android → Приложения → ZI Office → Уведомления |
| Обновление скачалось, но установка блокируется | разрешите приложению установку из этого источника (системный запрос) |

Со стороны GitHub: релиз должен быть именно
**Release** (не draft и не pre-release) с APK-файлом в ассетах — тогда
`releases/latest` его отдаёт. Для способа с токеном релизы остаются в
приватном репозитории — это нормально и никуда публиковать их не нужно.

## Частые вопросы

**Зачем нельзя просто положить APK в приватный репозиторий?**
Телефон не знает пароль/токен к приватному репозиторию, а вшивать токен в APK
нельзя — его вытащат из файла.

**Безопасно ли устанавливать обновление так?**
APK скачивается только с официальных доменов GitHub (проверка в
`UpdateManager.isSafeHost`) и подписан тем же ключом, что и текущая версия —
Android не даст установить APK с другой подписью без удаления приложения.

**Что будет, если ничего не настраивать?**
Приложение просто не найдёт новых версий и молча продолжит работать.

# Автосборка APK и автообновление ZI Office

Как это работает:

1. Приложению **нельзя** брать обновления из этого репозитория — он приватный
   (в нём лежит ключ подписи).
2. Поэтому нужен **публичный** репозиторий только для готовых APK-релизов:
   по умолчанию `zigorminsk-debug/ZI-Office-Release`.
3. Любой коммит в `main` или в ветку `arena/*` → workflow «Сборка APK»
   (`.github/workflows/build.yml`) собирает release-APK, прогоняет тесты и
   выкладывает APK **артефактом** — его можно скачать со страницы запуска
   (Actions → запуск → Artifacts).
4. Тег вида `v2.24` → workflow «Релиз APK» (`.github/workflows/release.yml`)
   собирает APK версии 2.24 и публикует GitHub Release с файлом
   `ZIOffice-2.24.apk` в публичном репозитории обновлений.
5. Приложение (класс `UpdateManager`) раз в 6 часов обращается к
   `https://api.github.com/repos/<RELEASE_REPO>/releases/latest`,
   сравнивает версию со своей и, если появилась новая, показывает диалог
   «Скачать». После скачивания Android сам предлагает установить APK поверх
   (подпись та же, данные сохраняются).

Номер сборки (`versionCode`) считается из `versionName` автоматически:
`2.24 → 20400`, `2.24.1 → 20401`. Поэтому обновление всегда «новее»
установленной версии и Android его принимает. В workflow номер версии берётся
из тега, файлы править не нужно.

## Одноразовая подготовка (10 минут)

### 1. Создать публичный репозиторий для релизов

На github.com → New repository:

- Owner: `zigorminsk-debug`
- Name: `ZI-Office-Release`  (именно так — приложение и workflow уже смотрят туда)
- **Public**
- README не нужен — просто пустой репозиторий.

Если хотите другое имя — поменяйте его в двух местах:

- переменная репозитория `RELEASE_REPO` (Settings → Secrets and variables →
  Actions → Variables) — она используется в workflow и передаётся в сборку;
- либо правка значения по умолчанию в `app/build.gradle`
  (`findProperty('releaseRepo')`) и в `.github/workflows/release.yml`.

### 2. Создать токен и добавить в секреты

GitHub → Settings (ваш аккаунт) → Developer settings → Fine-grained personal
access tokens → Generate new token:

- Repository access: **Only select repositories** → `zigorminsk-debug/ZI-Office-Release`
- Permissions: **Contents** → **Read and write**
- Срок: любой (например, 30 дней; при истечении просто обновить секрет).

Затем в этом репозитории:
Settings → Secrets and variables → Actions → New repository secret:

- Name: `RELEASE_TOKEN`
- Value: токен

> Токен нужен **только** для workflow — он хранится в секрете GitHub и в код
> не попадает. Код ZI-Office и ключ подписи остаются в приватном репозитории.

Пока секрет не задан, «Релиз APK» всё равно собирает APK и создаёт релиз
**в этом (приватном) репозитории**, а в описании запуска печатает памятку —
автообновление у пользователей при этом работать не будет.

## Как выпустить новую версию

```bash
git tag v2.24
git push origin v2.24
```

Всё. Workflow соберёт APK с версией 2.24 (и правильным номером сборки) и
опубликует релиз в публичном репозитории. С этого момента владельцы приложения
видят диалог обновления при следующем запуске (проверка — раз в 6 часов;
принудительно — долгое нажатие на заголовок главного окна → «Проверить
обновления»).

Альтернатива тегам: Actions → «Релиз APK» → Run workflow → указать номер
версии (например `2.24`). Тег workflow создаст сам.

### Если версия не совпала с файлом

В `app/build.gradle` остаётся `versionName "2.23"` — это нормально: workflow
передаёт свою версию в сборку (`-PversionName=2.24`). Чтобы номер версии в
файле не отставал, можно перед тегом обновить и его.

## Проверка сборки без релиза

Workflow «Сборка APK» запускается на каждый пуш в `main`, в ветки `arena/*`
и на пул-реквесты: собирает APK, прогоняет юнит-тесты и кладёт APK в
артефакты запуска. Если сборка красная — в описании запуска есть хвост лога,
а также создаётся issue с текстом ошибки.

## Частые вопросы

**Зачем нельзя просто положить APK в приватный репозиторий?**
Телефон не знает пароль/токен к приватному репозиторию, а вшивать токен в APK
нельзя — его вытащат из файла.

**Безопасно ли устанавливать обновление так?**
APK скачивается только с официальных доменов GitHub (проверка в
`UpdateManager.isSafeHost`) и подписан тем же ключом, что и текущая версия —
Android не даст установить APK с другой подписью без удаления приложения.

**Что будет, если забыть про токен/репозиторий?**
Приложение просто не найдёт новых версий и молча продолжит работать, ошибки
не показывает. О том, что настройка не завершена, workflow скажет в описании
запуска.

**Почему Android просит разрешить установку из этого источника?**
Это стандартный запрос системы для любого APK, скачанного не из Play.
Разрешение `REQUEST_INSTALL_PACKAGES` объявлено в манифесте; при первой
установке система покажет окно — нужно разрешить.

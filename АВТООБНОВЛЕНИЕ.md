# Автообновление ZI Office через GitHub

Как это работает:

1. Приложению **нельзя** брать обновления из этого репозитория — он приватный.
2. Поэтому нужен **публичный** репозиторий только для готовых APK-релизов:
   по умолчанию `zigorminsk-debug/ZI-Office-Release`.
3. Когда на `main` появляется тег вида `v2.24`, GitHub Actions
   (`.github/workflows/release.yml`) собирает release-APK и публикует
   GitHub Release с файлом `ZIOffice-2.24.apk` в публичном репозитории.
4. Приложение (класс `UpdateManager`) раз в 6 часов дёргает
   `https://api.github.com/repos/zigorminsk-debug/ZI-Office-Release/releases/latest`,
   сравнивает версию со своей (`versionName` из `app/build.gradle`) и, если
   версия новее, показывает диалог «Скачать». После скачивания Android сам
   предлагает установить APK поверх (подпись та же, данные сохраняются).

## Одноразовая подготовка (10 минут)

### 1. Создать публичный репозиторий для релизов

На github.com → New repository:

- Owner: `zigorminsk-debug`
- Name: `ZI-Office-Release`  (именно так — приложение и workflow уже смотрят туда)
- **Public**
- README не нужен, вестник не нужен — просто пустой репозиторий.

Если хотите другое имя — поменяйте его в двух местах:
- `app/src/main/java/com/docreader/app/UpdateManager.java` → константа `RELEASE_REPO`;
- `.github/workflows/release.yml` → строка `RELEASE_REPO: ${{ vars.RELEASE_REPO || '...' }}`
  (или задайте переменную репозитория `RELEASE_REPO` в Settings → Secrets and variables → Variables
  — она переопределяет значение по умолчанию).

### 2. Создать токен и добавить в секреты

GitHub → Settings (ваш аккаунт) → Developer settings → Fine-grained personal access tokens →
Generate new token:

- Repository access: **Only select repositories** → `zigorminsk-debug/ZI-Office-Release`
- Permissions: **Contents** → **Read and write**
- Срок: любой (например, 30 дней; можно продлевать, при истечении обновить секрет).

Затем в этом репозитории:
Settings → Secrets and variables → Actions → New repository secret:

- Name: `RELEASE_TOKEN`
- Value: токен

> Токен нужен **только** для workflow — он хранится в секрете GitHub и в код
> не попадает. Сам код ZI-Office и ключ подписи остаются в приватном
> репозитории.

## Как выпустить новую версию

1. В `app/build.gradle` увеличить версию:
   ```gradle
   versionCode 27
   versionName "2.24"
   ```
2. Закоммитить изменения и запушить на `main`.
3. Создать тег по номеру версии:
   ```bash
   git tag v2.24
   git push origin v2.24
   ```
   GitHub Actions соберёт APK и сам создаст релиз в публичном репозитории.

Альтернатива тегам: Actions → «Сборка и релиз APK» → Run workflow →
указать номер версии (например `2.24`) — тег workflow создаст сам.

С этого момента владельцы приложения видят диалог обновления при следующем
запуске (проверка — раз в 6 часов; принудительно — долгое нажатие на заголовок
главного окна → «Проверить обновления»).

## Проверка сборки

`.github/workflows/build.yml` компилирует проект на пулы в `main` и на пуши
в ветки `arena/*`. Если сборка красная — в логах будет ошибка компиляции.

## Частые вопросы

**Зачем нельзя просто положить APK в приватный репозиторий?**
Телефон не знает пароль/токен к приватному репозиторию, а вшивать токен в APK
нельзя — его вытащат из файла.

**Безопасно ли устанавливать обновление так?**
APK скачивается только с официальных доменов GitHub (проверка в
`UpdateManager.isSafeHost`) и подписан тем же ключом, что и текущая версия —
Android не даст установить APK с чужой подпиской без удаления приложения.

**Что будет, если забыть про токен/репозиторий?**
Приложение просто не найдёт новых версий и молча продолжит работать, ошибки
не показывает.

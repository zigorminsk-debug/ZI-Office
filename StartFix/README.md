# ZI Office StartFix

Автономная утилита для Windows, которая **восстанавливает кнопку и меню «Пуск»**,
поиск и панель задач.

Поддерживаются: **Windows 10, Windows 11, Windows Server 2012 / 2012 R2 / 2016 /
2019 / 2022 / 2025** (а также Windows 7 / 8 / 8.1 — в части, где это возможно).

---

## Готовые файлы

| Файл | Назначение |
|------|------------|
| `dist/StartFix-x64.exe` | **основной вариант**: графическое окно + режим `/cli` (64-битные системы) |
| `dist/StartFix-cli-x64.exe` | только консоль (когда графическое окно недоступно) |
| `dist/StartFix-x86.exe` | графическое окно для 32-битных систем |
| `dist/StartFix-cli-x86.exe` | консоль для 32-битных систем |
| `dist/ZI-Office-StartFix-1.0.0.zip` | архив со всеми файлами — для переноса на проблемный ПК |

Утилита **не требует** установки .NET, Visual C++ Redistributable, UCRT и
других компонентов — это один самодостаточный EXE (~400 КБ). Скрипты ремонта
встроены внутрь исполняемого файла и распаковываются автоматически.

> **Права администратора.** Утилита помечена как `requireAdministrator`,
> поэтому при запуске Windows сама покажет запрос UAC. Если меню «Пуск» не
> работает и открыть Проводник не удаётся — запустите программу через
> Диспетчер задач (`Ctrl+Shift+Esc` → «Файл» → «Запустить новую задачу» → имя файла).
> Windows Server 2012/2016: если открыт только Server Core — графической
> оболочки в системе нет, меню «Пуск» восстанавливать нечего.

## Как пользоваться (по шагам)

1. Скопируйте `StartFix-x64.exe` на проблемный компьютер и запустите
   (двойной клик → да, разрешить изменения).
2. Нажмите **«ДИАГНОСТИКА»** — утилита проверит систему и ничего не изменит.
   В журнале появится список найденных причин, а в папке отчётов — файл отчёта.
3. Нажмите **«ПОЛНЫЙ РЕМОНТ (рекомендуется)»** и дождитесь окончания
   (обычно 1–3 минуты).
4. **Перезагрузите компьютер** (кнопка «Перезагрузить ПК» в утилите).
5. Если меню «Пуск» всё ещё не открывается — выполните по очереди
   **«SFC»** и **«DISM»** (10–40 минут каждый), затем повторите шаг 3.

Кнопка **«Откат изменений»** возвращает параметры реестра и раскладку меню
«Пуск» из последней резервной копии.

## Что именно делает утилита

Ремонт выполняется по этапам (каждый этап — отдельный проход):

| Этап | Что проверяется и исправляется |
|------|-------------------------------|
| Диагностика | версия и разрядность системы, права, свободное место, перекос системных часов, незавершённая перезагрузка, службы, процессы `explorer.exe` / `StartMenuExperienceHost` / `ShellExperienceHost` / `sihost`, события падений за 14 дней, наличие сторонних «заменителей» меню «Пуск» |
| Точка восстановления | `Checkpoint-Computer` — штатная точка восстановления Windows |
| Резервные копии | экспорт в `.reg`: `Explorer\Advanced`, `Taskband`, `CloudStore`, политики оболочки, значения `Winlogon` |
| Реестр | подмена оболочки в `Winlogon` (`Shell`, `Userinit`), перехваты запуска процессов (`IFEO\Debugger` для `explorer.exe`, `sihost.exe`, `StartMenuExperienceHost.exe`, `ShellExperienceHost.exe`, `SearchHost.exe`, `SearchApp.exe`, `Cortana.exe`), внедряемые библиотеки `AppInit_DLLs`, устаревшие параметры `EnableXAMLStartMenu`, `Start_ShowClassicMode`, `TaskbarSmallIcons` |
| Службы | включает отключённые и запускает остановленные: `AppXSvc`, `ClipSVC`, `StateRepository`, `TileDataModelSvc`, `AppReadiness`, `Appinfo`, `CoreMessagingRegistrar`, `SystemEventsBroker`, `BrokerInfrastructure`, `DcomLaunch`, `RpcSs`, `RpcEptMapper`, `Themes`, `ProfSvc`, `UserManager`, `TabletInputService`, `ShellHWDetection`, `WSearch`, `Winmgmt`, `TrustedInstaller`, `UsoSvc`, `wuauserv` |
| Компоненты меню «Пуск» | `Reset-AppxPackage` и повторная регистрация `Microsoft.Windows.StartMenuExperienceHost`, `Microsoft.Windows.ShellExperienceHost` (в т. ч. напрямую из `C:\Windows\SystemApps`), а на Windows 11 — и оболочки поиска |
| Сброс раскладки | переименовывает `LocalState`/`TempState` компонентов меню «Пуск», `AppsFolder.*itemdata-ms`, очищает кэш плиток `CloudStore` и раскладку панели задач (`Taskband`) — меню «Пуск» возвращается к состоянию «как после установки» |
| Поиск | перезапуск службы `WSearch`, перерегистрация `Microsoft.Windows.Search` и `Cortana`, сброс состояния поиска |
| Проводник | корректный перезапуск `explorer.exe` (без повышенных прав) и компонентов оболочки |
| SFC | `sfc /scannow` + разбор `CBS.log` с заключением: повреждения устранены или требуют DISM |
| DISM | `Dism /Online /Cleanup-Image /ScanHealth` и `/RestoreHealth`, затем контрольный `sfc /scannow` |
| Все приложения | повторная регистрация всех AppX-пакетов пользователя |
| Откат | возврат переименованных каталогов и импорт всех `.reg` из последней резервной копии |

Каждый шаг протоколируется: журнал сессии, журнал шага, «сырой» вывод PowerShell,
список заключений и **HTML-отчёт** с итогами.

**Расположение файлов** (создаются автоматически):

```
%ProgramData%\ZI-StartFix\
    scripts\                     — распакованные скрипты PowerShell
    Reports\2026-09-23_11-30-00\  — session-*.log, findings-*.txt, console-*.log, report-*.html
    Backup\2026-09-23_11-30-00\   — *.reg, actions.txt, winlogon-values.txt
```

Кнопка **«Отчёты и журналы»** открывает папку отчётов.

## Режим командной строки

```
StartFix-x64.exe /cli /diag          — только диагностика
StartFix-x64.exe /cli /full          — полный ремонт
StartFix-x64.exe /cli /rollback      — откат последней резервной копии
StartFix-x64.exe /cli /?             — вся справка
```

Ключи: `/quick`, `/start`, `/search`, `/explorer`, `/sfc`, `/dism`, `/apps`,
`/layout|/nolayout`, `/norestorepoint`, `/norestart`, `/reboot|/noreboot`,
`/verbose`, `/folder`.

Консольная сборка (`StartFix-cli-x64.exe`) без параметров показывает
интерактивное меню. Коды возврата: `0` — успешно, `1` — с замечаниями,
`2` — ошибка, `3` — нет прав администратора, `4` — неподдерживаемая система.

Скрипты можно запускать и напрямую (PowerShell 5.1):

```powershell
powershell -ExecutionPolicy Bypass -File zi-repair.ps1 -Mode diag -Log diag.log
```

## Сборка из исходников

Нужен компилятор **zig** (в нём есть `zig cc` и компилятор ресурсов `zig rc`)
и Python 3:

```bash
pip install ziglang            # или установите zig вручную
./build.sh                     # соберёт 4 EXE в dist/ и архив
```

Сборка использует `-nostdlib` и системные библиотеки Windows напрямую —
никаких заголовков и библиотек Microsoft не требуется, поэтому результат
работает даже на Windows Server 2012 без обновлений.

Проверка кода:

```bash
./test/run_tests.sh            # 59 модульных тестов (строки, формат, чтение журнала)
node tools/check_ps_syntax.mjs scripts/*.ps1   # синтаксис PowerShell
```

## Если ремонт не помог

1. Выполните «SFC», затем «DISM», после чего повторите «Полный ремонт».
2. Проверьте систему **в новой учётной записи**: если там меню «Пуск» работает —
   повреждён профиль пользователя (пересоздайте его).
3. Удалите сторонние программы, заменяющие меню «Пуск» (StartAllBack, Start11,
   Open-Shell, ExplorerPatcher и подобные) — они часто и есть причина.
4. Проверьте системные часы: неверное время ломает запуск приложений меню «Пуск».
5. Крайняя мера — обновление Windows «поверх» (in-place upgrade) с сохранением
   файлов и программ.

## Ограничения

* Утилита работает с настройками **текущего пользователя** (для доменных и
  серверных систем запускайте её в контексте проблемной учётной записи).
* Windows 7 / 8 / Server 2008 R2: современного меню «Пуск» там нет, поэтому
  проверка пакетов AppX пропускается, исправляются только реестр, службы и оболочка.
* Точка восстановления не создаётся, если защита системы отключена или с момента
  предыдущей точки прошло менее 24 часов — в этом случае всё равно создаются
  резервные копии реестра.
